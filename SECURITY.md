# Security

Проверка выполнена 24 октября 2026 года. Это статическая браузерная сборка с отдельным HTTP-сервером Node.js без npm-зависимостей.

## Исправления

- Импорт файлов проверяет схему, типы, игровые тиры, числовые значения и ссылки на колонки. Ограничения: 4 MiB на файл, 20 файлов за раз, 64 колонки, 20 000 предметов. Зарезервированные ключи прототипов и поля экспорта отклоняются.
- Ссылки `#share=` распаковываются потоково с ограничением результата 4 MiB. После декодирования применяется та же проверка схемы. Исполняемый код из JSON не запускается.
- HTTP-сервер привязан к `127.0.0.1`, проверяет Host/Origin, отклоняет межсайтовые запросы и методы записи. Файлы за пределами public, скрытые пути, NTFS-потоки и выход через символьные ссылки не обслуживаются.
- Добавлены CSP без `unsafe-eval` и встроенных исполняемых скриптов, `nosniff`, запрет фреймов, ограничение referrer и разрешений браузера. Inline CSS оставлен для исходной MUI/Emotion-сборки.
- Групповое копирование заменяет совпадающий предмет только в целевой ячейке и сохраняет предметы других команд.

Проверки: `npm test`, `npm run check:vehicles`, `npm run scan:secrets`.

## Секреты и публикация

Сканер проверяет известные форматы ключей, JWT, приватные ключи, буквальные пароли, адреса с паролями и приватные ссылки Roblox. Он выводит только расположение совпадения, без значения. В проверенных файлах секретов не обнаружено. Сканер не гарантирует обнаружение произвольной строки-пароля.

Публикуемая папка собирается по явному списку разрешённых файлов. Браузерные профили, localStorage, локальные скриншоты, исходные HTML-снимки, архивы и резервные копии туда не входят. Пользовательские пресеты удалены; остаются шесть исходных пресетов. Приватные серверные ссылки не включаются.

## Сторонняя сборка и границы проверки

В браузерных файлах определены React/React DOM 18.3.1 и Next.js 15.5.12. Полного lockfile и исходников исходного приложения нет; автоматически проверить версии всех встроенных библиотек нельзя. `npm audit` не является аудитом этих минифицированных файлов.

У Next.js есть опубликованные серверные уязвимости. Например, [GHSA-2464-fhr4-w9xw](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw) относится к Image Optimization API, а [GHSA-673q-mjm6-r5xr](https://github.com/vercel/next.js/security/advisories/GHSA-673q-mjm6-r5xr) — к серверным `use cache`. В этом проекте Next.js-сервер, оптимизация изображений, Server Actions и React Server Components не запускаются: обслуживаются готовые файлы. Соответствующие серверные точки входа отсутствуют. [React также разграничивает приложения с серверными компонентами и приложения без сервера](https://react.dev/blog/2025/12/11/denial-of-service-and-source-code-exposure-in-react-server-components).

Это не означает отсутствия любых уязвимостей в старой клиентской сборке. Для полноценного обновления встроенных библиотек нужен исходный проект и повторная сборка. Файл `tools/upstream/index.js` — сохранённый материал для воспроизводимого применения патчей; сервер его не раздаёт.

Не меняйте серверную привязку на общедоступный интерфейс без отдельной проверки. Если размещаете public у другого хостера, настройте аналогичные HTTP-заголовки: мета-CSP не заменяет запрет встраивания через `frame-ancestors`.
